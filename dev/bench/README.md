# ASV runtime adapter for `github-action-benchmark`

A zero-build, client-side adapter that bridges the data output of [`benchmark-action/github-action-benchmark`](https://github.com)
(`data.js`) with the interactive web frontend of [**Airspeed Velocity (ASV)**](https://github.com).

This solution enables hosting an performance dashboard directly on static hosting (such
as GitHub Pages) without modifying existing CI/CD pipelines or running backend servers.

## Key features

* **Zero CI/CD Overhead:** Existing workflows using `github-action-benchmark` continue
  to append benchmark runs to `data.js` without any changes.
* **Purely Static & Serverless:** Runs entirely in the browser. Requires no backend
  databases, server-side rendering, or Node.js build steps.
* **Non-Invasive Integration:** Keeps the upstream ASV web assets completely untouched,
  isolating all custom logic and project settings in external files.
* **Declarative Transformation Pipeline:** Maps flat benchmark names into multi-dimensional
  ASV charts via a configurable pipeline.
* **Multi-Metric Extraction:** Splits a single benchmark entry into multiple independent
  charts.

## Architecture & How it works

### The problem
`github-action-benchmark` stores historical performance results in a single JavaScript
file (`data.js`) assigning an object to `window.BENCHMARK_DATA`. While convenient for
storage, its default frontend lacks multi-dimensional parameter filtering, hierarchical
grouping, and regression analysis views.

Conversely, **Airspeed Velocity (ASV)** provides a rich analytical UI (grid overview,
sortable summary tables, parameter selectors, and regression detection), but expects
a pre-compiled directory tree of static JSON files (`info.json`, `index.json`, etc)
generated by its Python CLI.

### The Solution: Virtual Filesystem Interception
Instead of introducing a build step in CI to materialize ASV's JSON hierarchy on disk,
this adapter constructs a **virtual filesystem in browser memory** at runtime:

```text
+-------------------+       +-------------------+       +-------------------------+
|    index.html     | ----> |    adapter.js     | ----> |        config.js        |
| (Bootstrap Shell) |       |  ($.ajax Hook &   |       | (Filters, Renames,      |
+-------------------+       |  Data Normalizer) |       |  Grouping & Metrics)    |
         |                  +-------------------+       +-------------------------+
         |                            |                              |
         v                            v                              v
+-------------------+       +-------------------+       +-------------------------+
|  www/index.html   | <---- | Virtual JSON Map  | <---- |         data.js         |
| (Unmodified ASV)  |       | (In-Memory Cache) |       | (window.BENCHMARK_DATA) |
+-------------------+       +-------------------+       +-------------------------+
```

1. **Bootstrap (`index.html`):** Fetches the unmodified `www/index.html`, rewrites
   relative asset URLs to point into `www/`, injects `adapter.js`, and renders the
   document while preserving top-level URL routing and hash navigation (`#BenchmarkName`).
2. **Dynamic Loading & Interception (`adapter.js`):** Hooks into `jQuery.ajax` before
   ASV initializes. When ASV requests any `.json` endpoint, the adapter intercepts
   the call, loads `config.js` and `data.js` on demand, compiles the virtual JSON
   payloads once, and resolves the Deferred promise directly from memory.
3. **Transformation Pipeline:** Raw benchmark entries are normalized through three
   stages:
   * **Filters:** Includes or excludes raw benchmark names using exact strings or
     regular expressions.
   * **Renames:** Applies sequential string or regex replacements to normalize naming
     conventions.
   * **Groups & Metrics:** Matches renamed identifiers against capture-group rules to
     extract the UI section, chart title, parameter axes, and numeric metric values.

## Directory structure

```text
gh-pages/dev/bench/
├── index.html           # Lightweight wrapper loading ASV and the adapter
├── adapter.js           # Core runtime engine and virtual filesystem (immutable)
├── config.js            # Project-specific rules, filters, and grouping (editable)
├── data.js              # Benchmark history managed by github-action-benchmark
└── www/                 # Upstream static web assets from airspeed-velocity/asv
    ├── index.html
    ├── asv.js
    ├── asv.css
    └── ...
```

## Quick start

### 1. Obtain upstream ASV web assets
Extract only the `asv/www` directory from the official ASV repository without installing
Python dependencies:

```bash
git clone --depth 1 --filter=blob:none --sparse https://github.com.git asv_repo
cd asv_repo && git sparse-checkout set asv/www && cd ..
mv asv_repo/asv/www ./www
rm -rf asv_repo
```

### 2. Deploy adapter files
Place `index.html`, `adapter.js`, and `config.js` in the root directory alongside
`data.js` and the `www/` directory.

### 3. Configure the project
Either edit `config.js` manually or run the interactive generator against an existing `data.js`.

### 4. Local preview
Because browsers restrict `fetch()` requests over the `file://` protocol, serve the directory using any local HTTP server:

```bash
python3 -m http.server 8000
```

Open `http://localhost:8000/` in a web browser.

## Configuration reference (`config.js`)

All project-specific behavior is controlled via `window.ADAPTER_CONFIG`:

```javascript
window.ADAPTER_CONFIG = {
  dataUrl: "./data.js",
  project: "project-name",
  branch: "master",
  machine: "ci-runner",
  regressionThreshold: 1.10, // Flag slowdowns greater than 10%

  filters: {
    include: [/.*/],
    exclude: [/experimental_/]
  },

  renames: [
    { match: /_baseline\b/g, replace: " [baseline]" }
  ],

  groups: [
    {
      match: /^([^/]+)\/([^/]+)\$/,
      section: "\$1",
      chart: "\$2",
      params: { variant: "default" }
    }
  ]
};
```

### Rule Mechanics

* **`filters.include` / `filters.exclude`:** Evaluated against the **raw** benchmark name
  before any transformations. Accepts exact strings (`"BM_Sort"`) or `RegExp` literals
  (`/BM_.*_tmp/`).
* **`renames`:** An ordered array of `{ match, replace }` rules applied sequentially.
  Avoid introducing parentheses `(...)` in renamed strings, as ASV reserves parentheses
  for formatting parameter tuples in summary tables; use square brackets `[...]` instead.
* **`groups`:** Evaluated top-to-bottom until the first `match` succeeds:
  * `section`: Top-level heading in the ASV Benchmark Grid.
  * `chart`: Individual chart name within the section (supports `$1`, `$2` capture group
    interpolation or custom functions `(match) => ...`).
  * `params`: Key-value map defining interactive parameter selectors inside the chart view.
  * `metrics` *(optional)*: Array of metric definitions allowing a single benchmark to
    populate multiple charts (e.g., extracting `cpu` or `iterations` parsed from Google
    Benchmark's `extra` field).

## Language configuration examples

### C++ (Google Benchmark)
Parses templated fixtures and thread counts such as `Fixture<ImplA>/Insert/threads:4`:

```javascript
groups: [
  {
    match: /^([^<]+)<([^>]+)>\/(?!threads:)([^/]+)(?:\/threads:(\d+))?\$/,
    section: "\$1",
    chart: "\$3",
    params: {
      implementation: "\$2",
      threads: (m) => `threads:${m.at(4) || 1}`
    },
    metrics: [
      { section: "\$1 (Wall Time)", unit: (b) => b.unit, getValue: (b) => Number(b.value) },
      { section: "\$1 (CPU Time)",  unit: "ns",          getValue: (b, extra) => extra.cpu ?? null }
    ]
  }
]
```

### Go (`testing.B`)
Parses sub-benchmarks and `GOMAXPROCS` suffixes such as `BenchmarkEncode/JSON-8`:

```javascript
groups: [
  {
    match: /^Benchmark([^/]+)\/(.+)-(\d+)\$/,
    section: "Go Benchmarks",
    chart: "\$1",
    params: {
      variant: "\$2",
      gomaxprocs: "\$3"
    }
  }
]
```

### Rust (`Criterion`)
Parses hierarchical Criterion IDs such as `throughput/hash_map/1024`:

```javascript
groups: [
  {
    match: /^([^/]+)\/([^/]+)\/(.+)\$/,
    section: "\$1",
    chart: "\$2",
    params: {
      input_size: "\$3"
    }
  }
]
```

### Java (`JMH`)
Parses fully qualified method names such as `org.example.CacheBenchmark.lookup`:

```javascript
groups: [
  {
    match: /^.+\.([^.]+)\.([^.]+)\$/,
    section: "\$1",
    chart: "\$2",
    params: {
      variant: "default"
    }
  }
]
```
